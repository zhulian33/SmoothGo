# SmoothGo 微信小程序

把网页版的核心体验（一句话生成行程 → 时间线 → 地图 → 排队估算）搬进微信小程序。
同一套地点库、同一套打分算法、同一套排队模型，**不同的是它完全不联网**。

排版也跟着网页版走：黑白两色、宋体标题、1px 细线分隔、**没有圆角**。
四个页面的顺序和内容都对齐 `web/index.html` 里的四个 view，数据从哪来的、
哪些是估算，也照网页版写在页面上。

## 一分钟跑起来

1. 打开 **微信开发者工具**（[下载](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)，选「稳定版」）
2. 左侧选 **小程序** → 点 **导入项目**
3. **目录**：选这个 `miniprogram/` 文件夹（不是仓库根目录）
4. **AppID**：点旁边的 **「测试号」**
   - 没有注册过小程序也能用，DevTools 会给一个临时 AppID
   - 如果连测试号都不给，用 **游客模式** 也能在模拟器里跑
5. **后端服务**：选 **不使用云服务**
6. 点 **导入** → 模拟器里直接出首页

> `project.config.json` 里的 `appid` 写的是 `touristappid`，这就是「游客/测试」模式。
> 等你注册了真 AppID，把它替换掉就行，其余不用动。

## 四个页面

| Tab | 做什么 |
|---|---|
| **行程** | 一句话描述 → 提取预算/时间/天数/人数/兴趣 → 生成行程。右上角 `EN` 一键切英文 |
| **路线** | 时间线：每站到达时间、停留时长、排队区间、**排队依据**（如「周五 12:10 · 餐厅午市高峰」）。底部四个汇总；两个按钮：智能重排、在地图查看 |
| **地图** | 和网页版一样：标题区 → 搜索框 → 7 个筛选标签（餐厅 / 景点 / 长春特色 / 排队少 / 人均 ¥100 以下 / 4.5 分以上）→ 图层页签（行程路线 / 地标 / 景点 / 美食，各带数量）→ 地图 → 地点列表。图层页签长在地图卡的上沿、卫星与路况落在下沿脚注里，中间不放第四行控件。标注是自绘的墨点（`images/marker-dot.png`），不是微信默认的红色水滴。点标注或列表卡片出详情卡（评分 · 人均 · 营业 · 推算等候 + 依据），可加入路线或直接导航 |
| **排队** | 有行程时按每站到达时间估算；没行程时列当前时刻排队最长的地点。卡片顺序照网页版：名称 → 评分 · 人均 · 营业 → 数据来源 · 置信度 → 大字等候区间 + 依据。底部保留「公交数据未接入」的说明 |

## 为什么它能「不联网」

这是这个版本和网页版最本质的区别，也是它能跑起来的唯一原因：

- **地点库打包进代码**：574 个地点（23 条人工整理 + 551 条高德去重）随小程序发布，不打接口
- **打分和排队是纯函数**：`planner.js` / `queue-model.js` 从 `web/` 原样拷过来，Node 和 JSCore 都能跑
- **地图用微信原生组件**：`<map>` 由微信自己渲染，不需要高德 key，也不需要把域名加白名单
- **坐标天然对得上**：高德 POI 是 gcj02，微信地图也是 gcj02，不需要转换

微信小程序真正卡人的两条 —— 注册 AppID（要身份证+人脸）、**所有 request 域名必须已备案** ——
在这里全部绕开了，因为一个网络请求都没有。

代价写清楚了：**没有照片**。高德的图片在 `store.is.autonavi.com` 等 CDN 上，
要显示就得把这些域名逐个加进「downloadFile 合法域名」，那就又回到备案问题。
所以 `docs/mp_extract_places.mjs` 主动把 `photos` 字段剔掉了。

## 改了网页版之后，怎么同步

```bash
python3 docs/build_miniprogram.py     # 需要 node 在 PATH 里
```

它做两件事：

1. `web/planner.js`、`web/queue-model.js` **逐字节**拷进 `utils/`
2. 调 `docs/mp_extract_places.mjs`，**直接执行 `web/app.js` 自己的合并逻辑**去生成
   `data/places.js` —— 不是重写一遍规则，所以去重规则以后再改，小程序也会跟着对

跑完 `data/places.js` 应该还是 574 条，测试会盯着这个数。

## 测试

```bash
npm run test:mini
```

12 个用例，在 Node 里用假的 `wx` 和 `Page` 把四个页面各跑一遍。能抓到：

- 页面 `onShow` 抛异常（中英文两种语言、有行程/无行程两种状态）
- 计划里的 `route` 是 id 没解析成对象（会渲染成一片空白卡片）
- 排队卡片缺「依据」
- WXML 读了页面没 `setData` 过的字段 —— 小程序不报错，直接渲染成空白
- WXML 用了没写样式的 class —— 同样静默，只会变成裸文本
- 「加入路线」没真的写进行程，「导航」没给出真实经纬度
- `app.json` 里指向不存在的页面或 tab 图标
- 照片字段偷偷回到数据里（= 又开始依赖网络）
- 切英文后 tab 栏还有中文

抓不到的：**布局**。样式好不好看只能用眼睛看模拟器。

## 别人能不能扫

**测试号阶段：不能。** 这一节值得单独说，因为它决定了你该走哪条路。

| 你现在有的 | 能用吗 |
|---|---|
| 开发者工具里的「预览」二维码 | 只有你自己能扫，且会过期 |
| **小程序码（葵花码）** | 拿不到 —— 必须由微信服务器生成 |
| 把代码发到别人手机 | 不行，微信小程序没有 APK 这种东西 |

微信的技术限制是硬的：**测试号（也称无 AppID / 游客 AppID）不支持上传代码**。
上传不了就没有版本管理，没有版本管理就没有「设为体验版」，没有体验版就没有
体验二维码，更不会有小程序码。开发者工具里那个灰色不可点的「上传」按钮就是这个原因。

小程序码同样不可能本地画出来：它是 `wxacode.get` / `getUnlimited` 接口用
AppID + AppSecret 换来的，而且要求小程序已经发布（生成 `scene` 指向特定页面时更是如此）。
所以「我想要一个能贴在 PPT 上的小程序码」和「我要正式上线」是同一件事。

## 想真发布要补什么

按顺序，缺一样都不行。三档可选，看你需要多少人能扫：

| 方案 | 谁能扫 | 要多久 |
|---|---|---|
| **体验版二维码** | 后台加为「体验成员」的人，个人主体上限 15 人 | 当天（注册 + 换 AppID + 上传） |
| **正式发布** | 任何人 | 备案 1–20 个工作日 + 审核 1–7 天 |
| 网页版 GitHub Pages | 任何人，任何手机浏览器 | 已有，只需后台开一下 Source |

步骤：

1. **注册小程序**（个人主体：身份证 + 人脸，免费）→ 拿到真 AppID
2. 用真 AppID 重新导入，`project.config.json` 里替换掉 `touristappid`
3. **补隐私协议**：一旦用 `wx.getLocation`、相册、剪贴板，必须在小程序后台填《用户隐私保护指引》
4. **上传 → 后台「管理 → 版本管理」→ 设为体验版 → 生成体验版二维码**
   → 再在「成员管理」里把朋友的微信号加进「体验成员」，对方才能扫开
5. 要让**不认识的人**也能扫：继续做 **ICP 备案**（2023 年 9 月起小程序本身也要备案，
   个人也能备，约 1–20 个工作日）→ 提交审核（1–7 天）→ 发布
   → 之后才能在「设置 → 基本设置 → 小程序码」下载葵花码

如果哪天真要接实时数据，第 5 步的域名备案就变成硬门槛了。
